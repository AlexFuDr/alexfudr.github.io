# Documentation context

- `product-requirements.md` is the product-scope source of truth; load it for requirement or roadmap decisions, not routine code edits.
- `translation-workflow.md` owns translator setup and editorial handoff instructions.
- `decisions/` records durable architectural decisions. Add a new ADR when an expensive-to-reverse decision changes; do not rewrite accepted history.
- Keep documentation concise and link to canonical code or schema instead of duplicating it.
- Update documentation in the same change when public commands, content workflow, deployment, or architecture changes.
