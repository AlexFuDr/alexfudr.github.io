# 针灸科学教育网站产品需求文档（PRD）

- 版本：0.2
- 状态：草案
- 日期：2026-10-14
- 产品负责人：Alex Fu
- 支持语言：英语（English）、荷兰语（Nederlands）
- 默认语言：荷兰语（Nederlands）

## 1. 产品概述

建设一个以科学化针灸教育为核心的网站，通过文章和视频帮助普通读者理解针灸的证据、适用范围、局限性与安全问题。网站同时提供一个低干扰的咨询入口，将确有需求的访问者引导至后续咨询渠道。

内容教育是第一目标，获客是优质内容与搜索可见性的自然结果，而不是以夸大疗效或批量制造 SEO 内容换取流量。

## 2. 产品目标

### 2.1 核心目标

1. 用通俗语言解释针灸研究、临床证据和安全知识。
2. 建立可验证的专业可信度，包括作者资历、引用来源、审阅记录和内容更新时间。
3. 让有明确需求的用户能够找到清晰的咨询入口。
4. 通过技术 SEO 和高质量内容获得与主题高度相关的自然搜索流量。

### 2.2 非目标

- 不提供在线诊断、急症处理或个体化治疗结论。
- 不承诺疗效，不使用“治愈”“保证有效”等绝对化表述。
- 不批量生成低价值的关键词页面。
- 不在本网站内设计或实现咨询表单、预约、支付或患者数据系统。
- MVP 阶段不自行托管视频文件。

## 3. 目标用户

### 3.1 求知型读者

- 想了解针灸是否有科学证据。
- 想知道治疗过程、风险与常见误解。
- 希望读懂研究结果，但缺少医学研究背景。

### 3.2 有潜在需求的用户

- 正在考虑针灸，希望先判断它是否适合自己的情况。
- 希望了解咨询方式、服务语言、执业范围和所在地。
- 可能来自鹿特丹、荷兰其他地区或线上内容覆盖的更广区域。

### 3.3 专业或半专业读者

- 针灸师、医疗从业者或相关专业学生。
- 需要快速查看文献出处、证据等级与研究局限。

## 4. 产品原则

1. **教育优先**：页面首先完整回答用户问题，咨询按钮不得遮挡或打断阅读。
2. **证据透明**：区分“有较一致证据”“证据有限”“尚不确定”和“未被支持”。
3. **安全优先**：明确禁忌、潜在不良反应、何时应寻求正规医疗或急救。
4. **作者负责**：每篇内容标明作者、资历、发布日期、最近审阅日期和利益冲突。
5. **不超出证据**：标题、摘要、结构化数据和正文必须表达一致，不制造点击诱饵。
6. **边界清晰**：教育内容与外部咨询服务明确区分。

## 5. 信息架构

### 5.1 一级栏目

- 首页
- 针灸基础
- 病症与证据
- 研究解读
- 安全与就诊指南
- 视频
- 关于作者
- 咨询与联系

以上栏目均提供英语和荷兰语版本。

### 5.2 建议内容集群

每个主题采用“支柱页 + 子文章 + 视频”的结构，例如：

- 针灸与慢性疼痛
  - 针灸如何研究疼痛
  - 临床指南如何评价针灸
  - 如何理解安慰针研究
  - 首次治疗前应了解什么
- 针灸安全
  - 常见不良反应
  - 无菌针具与感染控制
  - 哪些情况需要谨慎
  - 如何选择合格从业者

## 6. 功能需求

### 6.1 首页

- 用一句话说明网站的教育定位。
- 展示核心主题、精选文章和最新视频。
- 展示作者身份及完整介绍入口。
- 提供次要级别的咨询入口，不使用强制弹窗。
- 明确内容不能替代医疗诊断或紧急医疗服务。

### 6.2 文章系统

每篇文章至少包含：

- 清晰、描述性的标题和摘要。
- “本文回答什么”以及目标读者。
- 正文目录和语义化标题结构。
- 证据结论、证据局限和实际意义。
- 风险、安全提示及需要就医的情形。
- 可核验参考文献，优先链接到指南、系统综述和原始论文。
- 作者、审阅者（如有）、发布日期、最近审阅日期。
- 利益冲突及医学免责声明。
- 相关阅读和对应视频。

### 6.3 视频系统

- 视频托管在 YouTube、Vimeo 或后续选定的视频平台，网站提供独立观看页。
- 每个视频页包含标题、摘要、完整文字稿或详细讲义、章节时间点、参考文献和封面图。
- 视频信息与页面正文可独立被理解，不能只放一个播放器。
- 页面输出 `VideoObject` 结构化数据；条件允许时提供视频站点地图。

### 6.4 搜索与分类

- 支持按关键词搜索。
- 支持按主题、内容类型和证据状态浏览。
- 标签数量受控，避免产生大量内容稀薄的标签页。

### 6.5 语言切换

- 全站界面支持英语和荷兰语。
- 首次访问网站根路径时默认进入荷兰语版本。
- 导航栏提供清晰可见的 `English` / `Nederlands` 切换入口。
- 两种语言使用独立且稳定的 URL，例如 `/en/` 和 `/nl/`。
- 在某一页面存在对应翻译时，语言切换直接进入对应页面，而不是语言首页。
- 如果对应翻译尚未发布，切换入口进入目标语言首页，并明确提示该内容尚无对应版本。
- 记住用户主动选择的语言，但不根据 IP 地址强制跳转。
- 页面导航、按钮、搜索、标签、免责声明和系统提示均随语言切换。
- 每个语言版本单独维护标题、摘要、正文和 SEO 元数据，不使用未经人工审阅的自动翻译直接发布。

### 6.6 咨询入口

- 网站仅提供一个清晰、低干扰的入口或行动按钮。
- 入口可指向以后确定的外部联系或预约渠道。
- 当前项目不规定咨询页面、表单字段、预约流程、支付方式或后续客户管理流程。
- 咨询系统的产品、隐私、安全与合规需求另行立项。

### 6.7 关于作者与可信度

- 展示真实姓名、专业教育、可核验资质、当前执业状态和服务范围。
- 明确当前所在地和可提供服务的司法辖区；该信息在正式上线前确认。
- 提供编辑政策、证据评价方法、纠错政策和联系渠道。
- 不展示无法验证的头衔、荣誉或患者结果。

## 7. 内容与证据标准

### 7.1 证据优先级

1. 最新临床指南与权威机构文件。
2. 系统综述与 Meta 分析。
3. 随机对照试验和其他高质量原始研究。
4. 观察性研究。
5. 机制研究、传统理论和专家经验。

低层级证据不得被描述为已经证实临床疗效。每篇病症类内容应给出简明的证据确定性判断，并解释主要局限，例如样本量、偏倚、对照设计、效应大小和随访时间。

### 7.2 编辑流程

1. 明确用户问题与检索范围。
2. 使用 Nordon 执行可重复的 PubMed 检索，并保存检索式、检索日期和 PMID 集合。
3. 解析核心来源，生成结构化摘要、证据提取和跨文献综合材料。
4. 人工阅读并核对关键原文，确认研究设计、结果、局限和引用关系。
5. 撰写初稿，分别呈现收益、风险和不确定性。
6. 完成事实核查和引用核对。
7. 发布并记录下次审阅日期。
8. 出现重要新指南、安全信息或证据变化时提前更新。

### 7.3 Nordon 辅助研究流程

Nordon 作为内部证据检索与整理工具，不直接面向网站访问者，也不作为最终事实来源。

建议工作流：

1. 为每个主题定义结构化研究问题和纳入范围。
2. 使用可版本管理的 YAML 检索策略执行 `nordon fetch`，先以 `--dry-run` 检查 PubMed query。
3. 使用 PMID 解析入选文献，并保留原始来源链接。
4. 使用结构化摘要、证据提取和多文献综合功能建立证据表。
5. 使用综述草稿功能协助形成内容框架，但不直接发布生成文本。
6. 由作者回到原始论文和权威指南，逐条核对网站中的关键结论、数字和引用。
7. 将检索日期、检索策略版本和纳入文献记录保存为内部内容档案，以便后续更新。

质量约束：

- Nordon 输出属于研究辅助材料，不能替代专业判断或同行评议。
- 所有疗效、安全性和临床建议必须能够追溯到原始来源。
- 不引用无法获取或无法核验的二手摘要作为关键证据。
- 多篇研究之间存在冲突时必须如实呈现，不得只选择支持预设观点的结果。
- 自动生成的摘要、综合结论和参考文献必须经过人工复核。

## 8. SEO 需求

### 8.1 内容 SEO

- 每个页面只解决一个清晰的主要搜索意图。
- 优先回答真实问题，不以关键词密度为目标。
- 标题、URL、主标题和摘要自然一致。
- 建立主题集群和有意义的内部链接。
- 英文和荷兰文版本使用独立 URL，不在同一正文中并排混写。
- 多语言页面添加正确的 `hreflang` 和 canonical 标记。
- 每个页面包含指向自身及对应翻译的 `hreflang`，并设置合适的 `x-default` 页面。
- 两种语言的站点地图和内部链接都必须可被搜索引擎直接抓取。

### 8.2 技术 SEO

- 每页具备唯一的 title、meta description 和 canonical URL。
- 自动生成 XML sitemap、RSS 和 robots.txt。
- 使用语义化 HTML，确保移动端、速度和无障碍体验。
- 添加适用的 `WebSite`、`Person`、`Article`、`BreadcrumbList` 和 `VideoObject` 结构化数据。
- 在实际提供本地服务且地址等信息确认后，再添加准确的 `LocalBusiness` 或适用子类型数据。
- 接入 Google Search Console，提交 sitemap 并监控索引、搜索词、点击率和抓取问题。
- 域名或 URL 迁移时使用永久重定向，并保留旧 URL 映射。

### 8.3 医疗内容要求

针灸属于可能影响健康决策的内容。Google 对此类 YMYL 内容尤其重视准确性与可信度，因此必须突出实际经验、专业资质、来源质量、作者责任和透明度，而不是仅做页面关键词优化。

## 9. 域名与托管决策

### 9.1 域名要求

独立域名不是被 Google 收录的必要条件，但推荐在品牌正式启动前使用，原因包括品牌可信度、记忆性、迁移控制和未来更换托管平台时保持 URL 不变。

选择原则：

- 简短、容易口述和拼写，以品牌为主，而不是堆砌关键词。
- 避免连字符、数字和容易混淆的拼写。
- 若主要服务荷兰本地用户，可优先考虑 `.nl`。
- 若教育内容面向国际、多语言受众，可优先考虑中性的 `.com`。
- 可同时持有 `.nl` 和 `.com`，确定一个主域名，另一个做永久跳转。
- 域名中的精确关键词不是排名捷径，不能代替内容质量。

域名名称、品牌名称和主要服务区域目前均为待确认项。

### 9.2 GitHub Pages 是否可用

GitHub Pages 可以用于第一阶段：

- 静态文章、图片和嵌入式视频。
- Google 抓取与索引。
- sitemap、canonical、结构化数据和自定义域名。
- HTTPS。

但它不适合作为包含业务后台的完整平台：

- 只能原生托管静态页面，没有动态业务后台。
- 视频不应直接存放在仓库或 Pages 上。
- 动态预约、账户或支付等能力需要第三方服务或独立后端。
- GitHub 官方说明 Pages 不应主要用于经营在线业务、促成商业交易或 SaaS。

**建议：** 当前 GitHub Pages 作为内容 MVP 和原型继续使用；咨询入口指向独立渠道。开始稳定运营或确定品牌域名后，再评估是否迁移至长期托管平台。独立域名应尽早启用，以减少未来迁移对 SEO 的影响。

## 10. 隐私、安全与合规

- 本网站不收集咨询内容或健康信息；外部咨询渠道不属于本项目范围。
- 如使用访问分析或其他第三方服务，应提供相应隐私说明。
- 启用 HTTPS、安全响应头、依赖更新和最小权限。
- 分析工具采用隐私友好配置；非必要 cookie 在适用时取得同意。

## 11. 非功能需求

- 移动端优先，主流移动设备可正常阅读并打开咨询入口。
- 核心内容在 JavaScript 失败时仍可访问。
- 图片响应式加载并包含有意义的替代文本。
- 页面满足 WCAG 2.2 AA 的基础要求。
- 核心页面性能以良好的 Core Web Vitals 为目标。
- 外部视频不可用时提供文字稿或讲义。
- 发布过程具备预览、链接检查、HTML 检查和回滚能力。

## 12. 衡量指标

### 12.1 教育效果

- 文章有效阅读率和平均参与时间。
- 视频观看完成率。
- 相关阅读点击率。
- 内容纠错数量及更新及时性。

### 12.2 搜索表现

- 被索引的有效页面数。
- 非品牌自然搜索曝光和点击。
- 重点主题进入前 20 名的页面数量。
- 搜索结果点击率及富媒体结果有效率。

### 12.3 咨询入口

- 仅统计咨询入口点击率，不追踪或评估咨询内容。

## 13. 分阶段交付

### 阶段 0：定位确认

- 确定品牌名、主域名和主要受众地区。
- 确定专业身份、可公开资质和咨询服务边界。
- 确定首批 3 个内容主题集群。
- 为首批主题建立 Nordon 检索策略和证据档案规范。

### 阶段 1：内容 MVP

- 更新首页、栏目结构、作者页和免责声明。
- 建立 `/en/` 与 `/nl/` 双语目录、界面文案和语言切换。
- 发布 3 个支柱页及 6–10 篇支持文章。
- 建立文章模板、参考文献格式和编辑流程。
- 使用 Nordon 完成首批内容的可重复检索、证据提取和人工核验。
- 完成基础技术 SEO、Search Console 和站点地图。
- 提供指向外部渠道的咨询入口。

### 阶段 2：视频与多语言

- 发布独立视频观看页、文字稿和 `VideoObject` 数据。
- 扩充两种语言的内容覆盖率。
- 根据两种语言的真实搜索和读者反馈进行本地化关键词研究。

### 阶段 3：稳定运营

- 根据实际内容规模评估长期托管平台。
- 保持域名与 URL 稳定。
- 在服务地点与执业信息确认后开展本地 SEO。
- 咨询系统如有需要，另行立项。

## 14. 待确认事项

1. 目标是全球科普、荷兰本地获客，还是两者兼顾？
2. 当前可公开展示的学历、注册资质和执业范围是什么？
3. 是否有实体服务地点；如有，哪些信息可以公开？
4. 首批最有专业优势的三个病症或主题是什么？
5. 视频主要发布到哪个平台？
